For our third post in the Bootstrap 6 series, we're taking a look at all our new and improved components. We'll cover everything from new aesthetics, generative variants, the use of more native HTML elements, some new CSS strategies, and various dependencies.

Heads up though, we won't be covering any form components here yet—those will come later.

## What’s new

Honestly, nearly every component has been touched in some way, and many of them have been completely overhauled to implement new standards and features, update dependencies, and restyle for a more modern look and feel. Here's a little taste to start.

<ComponentWall />

Brand new components, or completely rewritten components, in v6 include:

- **Avatar** with sizes, status indicators, and `.avatar-stack` for grouped avatars
- **Chip** for tags and tokens (along with a Chip Input that we'll cover in the upcoming forms post).
- **Dialog** replaces Modal with native `<dialog>` element (including its native `showModal()`, `show()`, and `close()` APIs), plus new transition effects and styles.
- **Drawer**, like Dialog, replaces Offcanvas and is built on a shared architecture with Dialog.
- **Menu** replaces Dropdown with Floating UI for placement, new styles, new options, and more.
- **Nav overflow**, a wrapper that collapses whatever doesn’t fit in a wide navigation into an automatic overflow menu.
- **Prose** for scoping rich typography across long-form content.
- **Stepper** for multi-step workflows, CSS-only
- **Toggler**, a small plugin for toggling classes or attributes via `data-bs-toggle="toggler"`

Other components that have been significantly revamped in v6 include:

- **Accordion** was rebuilt with native `<details>` and `<summary>` elements, plus updated styles and options.
- **Breadcrumb** has new styles and divider options.
- **Button** has new base class styles, three new variants, new extra small and icon-only sizes, and more.
- **Card** has updated styles, namely around `border-radius` management and flexbox layout.
- **Carousel** was rebuilt on CSS scroll snap, prioritizing the modern content carousel paradigms over the traditional image-based slideshow. It also features revamped autoplay behavior, new controls, more flexible layout, multiple items at once, new end behaviors, and more.
- **Close button** was rebuilt to use CSS masks instead of SVGs, plus updated styles and better dark mode support.
- **Navbar** was rebuilt to use container queries and the Drawer component for its responsive behavior, plus a few other style updates.
- **Scrollspy** has a new detection strategy that's more robust and accurate.
- **Tooltip** and **Popover** have been rewritten to use Floating UI for their placement and are now always available (unlike in v5, where they were opt-in due to performance concerns).

We won't go into every change of every component, but our [migration guide](https://getbootstrap.com/docs/6.0/guides/migration) has an exhaustive list of all the changes (and how to migrate from v5 to v6) if you want to dig in. Instead, let's jump into spotlighting some of our favorite component changes.

## Buttons

Buttons just might be one of the most powerful Sass components in Bootstrap 6. Previously, we had few style variants for buttons—enable a global Sass variable for gradients and switch between default and outline styles. New in v6, we have [four style variants](https://getbootstrap.com/docs/6.0/components/button/#variants) plus a unique [styled hybrid modifier](https://getbootstrap.com/docs/6.0/components/button/#styled-buttons), [four sizes](https://getbootstrap.com/docs/6.0/components/button/#sizes), and an [icon-only option](https://getbootstrap.com/docs/6.0/components/button/#icon-buttons).

<button type="button" class="btn-solid theme-${color}">${themeColorTitle(color)}</button>
<button type="button" class="btn-outline theme-${color}">${themeColorTitle(color)}</button>
<button type="button" class="btn-subtle theme-${color}">${themeColorTitle(color)}</button>
<button type="button" class="btn-text theme-${color}">${themeColorTitle(color)}</button>`)} />

Building those variants with our new [theme system](/2026/08/21/bootstrap-6-colors/) took some work, but what we landed on feels super powerful for folks to customize—a series of interconnected Sass maps and mixins that work together to generate styles for every variant.

Like all other components, `_button.scss` starts with a `$button-tokens` Sass map for all the CSS variables we use. There are also separate `$button-link-tokens` and `$button-styled-tokens` maps for the link and styled variants. Button sizes are also a Sass map, `$button-sizes`, that works in conjunction with the variants map to generate styles for each size.

```scss
// Imports come first…

// Token maps next…
// Not shown here: $button-link-tokens and $button-styled-tokens
$button-tokens: () !default;s
$button-tokens: defaults(
  (
    // …
  ),
  $button-tokens
);

// Button sizes…
$button-sizes: () !default;
$button-sizes: defaults(
  ("xs", "sm", "lg"),
  $button-sizes
);
```

The variants map, `$button-variants`, is a more complex Sass map that defines each variant at the top level, then assigns theme token names to CSS properties for each button state. So for `.btn-solid`, the `background` and `border-color` use the same theme `bg` token. Each variant get's the manual mapping, meaning you can customize, remove, or add variants as desired.

```scss
$button-variants: defaults(
  (
    "solid": (
      "base": (
        "bg": "bg",
        "color": "contrast",
        "border-color": "bg"
      ),
      "hover": (
        "bg": "bg",
        "border-color": "bg",
        "color": "contrast"
      ),
      "active": (
        "bg": "bg",
        "border-color": "bg",
        "color": "contrast"
      )
    ),
    "outline": (
      "base": (
        "bg": "transparent",
        "color": "fg",
        "border-color": "border"
      ),
      "hover": (
        "bg": "bg",
        "color": "contrast",
        "border-color": "bg"
      ),
      "active": (
        "bg": "bg",
        "color": "contrast",
        "border-color": "bg"
      )
    ),
    // Plus 2 other variants…
  ),
  $button-variants
);
```

From the variants map, we generate a selector list needed for a shared ruleset for all the variants. That ruleset gets the tokens, styles, and more. The selector list lets us get away without needing a base class on every instance of a button in your HTML.

```scss
$btn-variant-selectors: (string.unquote(".btn"), string.unquote(".btn-link"), string.unquote(".btn-icon")) !default;
@each $variant, $config in $button-variants {
  $btn-variant-selectors: list.append($btn-variant-selectors, string.unquote(".btn-#{$variant}"), comma);
}
```

The output of that looks like this in our compiled CSS:
```css
.btn,
.btn-link,
.btn-icon,
.btn-solid,
.btn-outline,
.btn-subtle,
.btn-text {
  /* Tokens and styles… */
}
```

Then finally, the loop does all the heavy lifting and generates the styles for all our variants.

```scss
@layer components {
  #{$btn-variant-selectors} {
    @include tokens($button-tokens);

    // Shared base styles…
  }

  @each $variant, $config in $button-variants {
    .btn-#{$variant} {
      @each $property, $value in map.get($button-variants, $variant, "base") {
        @if $value == "transparent" {
          --btn-#{$property}: transparent;
        } @else {
          --btn-#{$property}: var(--theme-#{$value});
        }
      }
      // Plus other variant-specific styles…
    }
  }
  // Rest of the stylesheet…
}
```

## Components galore

Bootstrap 6 includes several brand new components and a few bottom-up rewrites to take advantage of newer HTML elements and standards, streamline JavaScript reliance, and leverage better CSS support.

There’s a single idea running through most of this work: for years we shipped JavaScript to do things browsers couldn’t do. Browsers can do them now, so much of v6 is less about new code than about deleting old code and letting the platform take over.

### Rebuilt on the platform

- **Dialog** replaces Modal, built on the native `<dialog>` element and its `showModal()`, `show()`, and `close()` APIs.
- **Drawer** replaces Offcanvas, and shares its show/hide lifecycle with Dialog through a common `DialogBase` class—so it’s a `<dialog>` element too.
- **Accordion** is rewritten on `<details>` and `<summary>`. Basic open and close needs no JavaScript at all, and exclusive groups use the HTML `name` attribute instead of `data-bs-parent`.
- **Carousel** is rebuilt on CSS scroll snap, prioritizing the modern content carousel over the traditional slideshow.
- **Navbar** collapses into a Drawer instead of a custom collapse.
- **Menu, Tooltip, and Popover** now position with Floating UI instead of the deprecated Popper.js.

Dialog is the clearest example of what that buys us. Here’s v5:

```html
<div class="modal fade" id="exampleModal" tabindex="-1">
  <div class="modal-dialog">
    <div class="modal-content">
      <div class="modal-header">
        <h1 class="modal-title fs-5">Modal title</h1>
        <button type="button" class="btn-close" data-bs-dismiss="modal" aria-label="Close"></button>
      </div>
      <div class="modal-body">…</div>
    </div>
  </div>
</div>
```

And v6:

```html
<dialog class="dialog" id="exampleDialog">
  <div class="dialog-header">
    <h1 class="dialog-title">Dialog title</h1>
    <button type="button" class="btn-close" data-bs-dismiss="dialog" aria-label="Close"></button>
  </div>
  <div class="dialog-body">…</div>
</dialog>
```

Two wrapper elements gone, and with them a lot of machinery. The browser now supplies the backdrop through `::backdrop`, the focus trap, and the inert top layer. Body scroll locking moved to CSS, where `:root.dialog-open` pairs with `scrollbar-gutter: stable` so the page doesn’t shift when a dialog opens.

Accordion tells the same story from a different angle:

```html
<details class="accordion-item" name="accordionExample" open>
  <summary class="accordion-header">
    Accordion Item #1
    <svg class="accordion-icon" viewBox="0 0 16 16" fill="none" stroke="currentColor"><path d="m2 5 6 6 6-6"/></svg>
  </summary>
  <div class="accordion-body">…</div>
</details>
```

No `.accordion-button`, no `.accordion-collapse`, no `data-bs-parent`, and no Collapse plugin. Open state styling is just `details[open]`.

Here it is running. Open one item and the others close, because they share a
`name`. There is no accordion JavaScript on this page at all.

### What we deleted

Rebuilding on native elements let us remove a long list of workarounds:

- `util/backdrop`, `util/focustrap`, and `util/scrollbar` — all three obsolete now that Dialog and Drawer are native `<dialog>` elements
- The carousel’s custom swipe handler, plus `.carousel-item-start`, `-end`, `-next`, `-prev`, and the `.carousel.pointer-event` helper — the browser tracks scroll position instead
- The `.modal-backdrop` element — `::backdrop` does it
- `.btn-close-white`, `.carousel-dark`, and the separate light and dark navbar toggler SVGs
- Popper.js, and the `.dropdown` wrapper, `.dropdown-toggle` class, and `<ul><li>` scaffolding that Menu no longer needs

Several of those deletions come from one change: icons are now CSS masks. The close button, navbar toggler, breadcrumb divider, carousel controls, and checkbox marks all render via `mask-image` tinted with `background-color: currentcolor`. They inherit the surrounding text color, which means dark mode works for free and we no longer need a second SVG or a `filter` hack for light-on-dark.

### Renamed and reshaped

Three components changed names along with their internals, and these are the renames that will show up in your markup:

- **Modal → Dialog.** Classes, data attributes, events, CSS variables, and the JavaScript export all follow: `.modal-body` becomes `.dialog-body`, `data-bs-toggle="modal"` becomes `data-bs-toggle="dialog"`, `show.bs.modal` becomes `show.bs.dialog`.
- **Offcanvas → Drawer.** Same mechanical rename throughout, plus a new `.drawer-sheet` variant for flush-to-edge panels and swipe-to-dismiss on touch devices.
- **Dropdown → Menu.** `.dropdown-menu` becomes `.menu`, `.dropdown-item` becomes `.menu-item`, and the wrapper and toggle classes are gone—the toggle and the `.menu` are just siblings. Direction is now `data-bs-placement` instead of `.dropup` and friends, and submenus are supported through `.submenu`.

The [migration guide](https://getbootstrap.com/docs/6.0/guides/migration) has the exhaustive mapping for all three.

### Carousel and autoplay

Rebuilding the carousel on scroll snap handed us a pile of features we didn’t have to write. Sliding, touch dragging, momentum, and keyboard scrolling are all just native scrolling now. On top of that we can show multiple slides at once, reveal a peek of the adjacent ones, add gaps, center the active slide, and support variable-width slides—all through CSS custom properties.

Autoplay changed too, and the new behavior is stricter. It’s opt-in via `data-bs-autoplay="true"`, the old `ride` option is gone, and interacting with a carousel now stops autoplay permanently rather than resuming it. The new `.carousel-control-play-pause` button gives visitors a discoverable way to stop and resume playback, which is what [WCAG 2.2.2](https://www.w3.org/TR/WCAG/#pause-stop-hide) requires—a hover-only pause doesn’t satisfy it.

### Brand new

- **Avatar** with sizes, status indicators, and `.avatar-stack` for grouped avatars
- **Stepper** for multi-step workflows, CSS-only
- **Nav overflow**, a wrapper that collapses whatever doesn’t fit in a wide navigation into an automatic overflow menu
- **Toggler**, a small plugin for toggling classes or attributes via `data-bs-toggle="toggler"`
- **Chip** for tags and tokens, plus **Prose** for scoping rich typography and **Form adorn** for decorating inputs

Navbar, nav overflow, list group, stepper, and card groups now respond to container queries rather than viewport width, so they adapt to the space they’re actually in. One thing to know if you’re upgrading: card groups and horizontal list groups need an ancestor query container, so add something like `.contains-inline` to a wrapper or they’ll stay stacked.

Drag the handle on the right to resize the container. The card group responds to
the space it's in, not to the width of your browser window.
